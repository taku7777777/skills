# モデル選択・委任の経済性のエビデンス

## 使い方

単価・倍率・製品挙動はすべて時点依存。成果物へ引用するときは確認日と出典URLを併記し、委任マトリクスの「見直し条件」に単価改定・モデル追加を明記する。SKILL.md には桁関係(単価比の桁感覚 1:3:5:10、Batch半額)だけを置き、具体額・倍率・製品挙動は本ファイルと一次URLを正とする。

## 一次情報

### 単価・課金構造(official)

- [Anthropic Pricing](https://platform.claude.com/docs/en/about-claude/pricing.md) — 2026-07-30参照、official。**単価の一次確認先はこのURLのみ**(`quality/sources.json` の `claude-pricing`)。他のファイルや他スキルのevidenceに同じ値の写しがあっても、突き合わせ先は常にここ — 写し側だけを更新すると閾値の導出が静かにずれる。
  - $/MTok(入力/出力): **Fable 5 $10/$50**、Opus 5系 $5/$25、Sonnet 5 $2/$10(導入価格)、Sonnet 4.6 $3/$15、Haiku 4.5 $1/$5。
  - **行の取り違え注意**: $15/$75 は deprecated の Opus 4.1 の行であってFable 5ではない。この行を取り違えるとトークン建て閾値の導出が約1.5倍きつくなる。トークン建ての値を導く前に、必ず上の行と一次URLを突き合わせる。
  - キャッシュ倍率: 書込 ×1.25(5分TTL)・**×2.00(1時間TTL)**、読み ×0.10。Fable 5基準なら1時間書込の実効は$20/MTok、cache readは$1/MTok(トークン建て閾値の導出はこの実効単価で割る)。
  - **Sonnet 5の導入価格は2026-08-31で終了**($2/$10 → $3/$15)。単価比の桁感覚(Haiku:Sonnet:Opus:Fable ≒ 1:3:5:10)はこの改定後の比。
  - Batch APIは入出力とも**50%割引**。キャッシュ倍率と乗算で重畳(例: Opus 5のBatch+cache readは $5×0.5×0.1 = $0.25/MTok)。
  - 出力単価は入力の5倍(全モデル共通の桁関係)。thinkingトークンは出力単価で課金。
  - **Claude 4.7以降のモデル(Opus 4.7+・Sonnet 5・Fable 5等)は新トークナイザで同一テキストが約30%多くトークン化される**(Sonnet 4.6以前は旧トークナイザ)— 単価が同じでも実効コストが変わるため、モデル間の金額比較を単価だけで行わない。
- [Message Batches API: Batch processing](https://platform.claude.com/docs/en/build-with-claude/batch-processing) — 2026-07-31参照、official。Batchの遅延特性はPricingページではなくこちらが出典。
  - **ほとんどのバッチは1時間以内**に完了。結果は全件完了時か24時間経過時のいずれか早い方で取得可能になり、**24時間で処理が終わらないバッチは期限切れ**(期限切れリクエストは課金されない)。**結果の取得可能期間は作成から29日**。
  - → 「リアルタイム性が不要か」の判断はこの遅延特性で切る。CI往復・対話的な修正を含む作業はBatchに載せない(`delegation-matrix.md` §4 実行形態の判断表)。

### Claude Codeの製品挙動(official)

- [Claude Code: Manage costs effectively](https://code.claude.com/docs/en/costs) — 2026-07-30参照、official。
  - 「予想外の高額請求は、クリアされない長セッションか**Opusが既定のまま**に大抵帰着する」。
  - 公式指針: Sonnetが大半のコーディングをこなす。Opusは複雑なアーキテクチャ判断・多段推論に温存。
  - **agent teamsはplanモード時に標準セッションの約7倍のトークン**を消費。teammatesはSonnetへ、チームは小さく、済んだらshut down。
  - エンタープライズ実績: 平均約$13/開発者/稼働日、90%のユーザーは$30/日未満(予算の桁感覚)。
- [Claude Code: Sub-agents](https://code.claude.com/docs/en/sub-agents) — 2026-07-30参照、official。
  - サブエージェントのfrontmatter `model:` で haiku/sonnet/opus/fable/フルID/inherit を指定可能(既定 inherit)。安価モデルへのルーティングは公式ユースケース。
  - **v2.1.198以降、組み込みExploreサブエージェントはHaiku固定ではなくメイン会話のモデルを継承する。** ただし**Claude APIでは継承モデルがOpus上限**(上位ティアのメイン会話でもExploreはOpus止まり。Sonnet/Haikuのセッションでは同じモデル)。Bedrock・Google Cloud・Microsoft Foundry等の他プロバイダ経由では上限なしでそのまま継承する。Fable常用環境で「ExploreもFableで走る」と読まないこと。いずれにせよ探索を安く保つには `model: haiku` のカスタムサブエージェント(組み込みと同名 `Explore` で上書きできる)を置く — 「組み込みの既定は製品バージョンで変わる」の代表例。
- [Claude Code: Prompt caching behavior](https://code.claude.com/docs/en/prompt-caching) — 2026-07-30参照、official。
  - サブエージェントは独立コンテキスト・独自キャッシュで、**初回コールはキャッシュゼロから始まり、サブスクリプションでも5分TTL固定**(本体セッションは1時間)。forkは例外的に親キャッシュを読める。
  - キャッシュはモデル別。セッション途中のモデル切替はキャッシュ全損 — 切替はセッション冒頭か `/clear` 直後で。
- [Claude Code: Best practices](https://code.claude.com/docs/en/best-practices) — 2026-07-30参照、official。
  - headlessファンアウトは「**最初の2〜3ファイルで失敗からプロンプトを磨いてから全量に回す**」。
  - 調査・実装後の検証・アドバーサリアルレビューはフレッシュ文脈のサブエージェントへ(コンテキスト溢れ対策としての委任は公式推奨 — 委任自体は悪ではない)。

### 実測(industry-research)

- [metsuke](https://github.com/taku7777777/metsuke) — 2026-07-30参照、industry-research。単一ユーザー・34,000超リクエストの実測にもとづく行動変容システム。桁の参考であり普遍値ではない。
  - **最上位モデル(Fable 5)が総額の53%を占有** — 「モデル選択はコンテキスト整理やキャッシュ運用より大きな桁で効く」。
  - サブエージェント費の誤帰属はagent系コストの約1/4・総コストの約5%。spawn連鎖で指示へ因果帰属しないと高額指示のランキングが逆転する(時間帯の重なりによる帰属は誤る)。
  - **外部エージェント委譲(Codex等)は計測範囲の外へコストを逃がす。** 委譲先に規約ファイル(AGENTS.md)が無いと委譲のたびにリポジトリ探索が繰り返され、その費用は手元の台帳に現れない。
  - counter-metrics: **手戻り率・上位モデル差し戻し率**(原典の指標名。本スキルが「差し戻し率」と呼ぶのは後者に対応する)。「高品質タスクは高価でよい。『安くする』だけをKPIにしない」。

## 定額レーンでのトークン建て代替閾値

上記のドル建ての数値(単価表、$13/開発者/稼働日、90%が$30/日未満)はすべて**API従量課金レーン**の値。定額プラン(サブスクリプション)には「requestごとの実請求額」という概念が無いため、これらの閾値はそのままでは発火しない。代替として下記を使う。データソースはローカルのセッショントランスクリプト(4入力の取得レシピは `llm-cost-observability` の data-sources.md)で、ドル換算を経由せずトークン量のまま扱える点が利点。まず `/status` でどの請求レーンにいるかを確定し、消費の内訳は `/usage`(Pro/Max/Team/Enterpriseではskills・subagents・プラグイン・MCPサーバ別の使用率も出る)で見る。**枠の上限値そのものが画面に出るとは限らない**ため、絶対トークン数の閾値は置かず、下記のように比率・消費速度で閾値を切る(上限値はプランと時期で変わるため本ファイルにも書かない)。

| ドル建て閾値 | 定額レーンでの代替 | 備考 |
|---|---|---|
| 「最上位モデルが総額の過半」(大原則1) | **最上位モデルのトークン構成比が過半** | 単価を掛けない純粋な消費量比。判定も打ち手も変わらない |
| 日次予算に対する消化率 | **週次枠・セッション枠の消費率 vs 期間の経過率**(5時間ローリング窓が公式に明記されているのはTeams/Enterpriseのシート許容量。Pro/Maxはsession limitとして案内される) | 上限値を知らなくても比較できる(枠の何%を、期間の何%の時点で使ったか)。消費率が経過率を上回る状態が続くなら上限に当たる。着地見込みを出して人へ提示する(自動停止しない — `llm-cost-observability` 大原則7) |
| agent teamsのコスト増 | **planモード時に標準セッションの約7倍のトークン** | もともとトークン建ての値。レーン非依存でそのまま使える |
| 「出力単価は入力の5倍」 | **出力トークン量を入力とは別に見る** | 5倍は課金の比率。定額レーンの枠が同じ重みで削られるかは公開されていないので断定しない。トランスクリプトの入出力トークン量と `/usage` の使用率表示の動き方を数日突き合わせて、自分のレーンでの効き方を確かめる |
| Batch半額($換算) | **代替なし(レーンをまたぐ)** | Batch APIはAPI従量課金側の機能で、Claude Codeの対話セッションから直接は使えない。移せば枠は空くがAPI実費が発生する。枠の節約とドルの発生は1つの総額に合算しない |

`references/worked-example.md` の金額(月$1,900 → $860)も従量課金レーンの例。定額レーンで同じ設計を適用した場合、モデル構成比の変化(89% → 31%)は同じように現れるが、成果は請求減ではなく週次枠の消費率低下として現れる。

## 更新規律

- 四半期ごと、およびモデル追加・価格改定の発表時に再確認する。直近の既知の改定予定: **2026-08-31のSonnet 5導入価格終了**。
- 単価が変わっても「モデル構成比を最初に見る」「割当は検証手段とペア」「二重払いの検出」「counter-metricsとセット運用」という安定原則はSKILL.mdに残す。
- metsukeの実測値は単一ユーザー環境の値。自チームの構成比・単価分布は自前の計測(`llm-cost-observability`)で再測定してから割当を決める。
