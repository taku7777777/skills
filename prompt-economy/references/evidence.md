# 依頼設計の経済性のエビデンス

## 使い方

数値・製品挙動を成果物へ引用するときは、参照日と出典を併記する。製品挙動(Esc・/rewind・planモード・compactの仕様)はClaude Codeのバージョンで変わりうるため、断定する前に現行ドキュメントで再確認する。metsukeの実測値は単一利用者・特定期間の観測であり無作為化比較ではない — 桁感覚の根拠として使い、他環境の予測値として転用しない。

## 一次情報

- [Claude Code Best practices](https://code.claude.com/docs/en/best-practices) — 2026-07-30参照、official(継続更新ページ)。検証手段の同梱が筆頭プラクティス: チェックがなければ人間が検証ループになり、全ミスが人間の発見待ちになる。**同じ問題で2回以上訂正したら、コンテキストは失敗アプローチで汚染されている — /clearして学びを織り込んだプロンプトで再開する方が、ほぼ常に長いセッションに勝る**。誤方向はEscで即停止(コンテキスト保持のままリダイレクト可能)。diffを一文で説明できるタスクはplanモードを飛ばす(planにもオーバーヘッドがある)。大きめ機能は「エージェントに自分をインタビューさせてSPEC.mdを書かせ、フレッシュセッションで実装」。無関係タスクの混載(kitchen sinkセッション)と、スコープなしの「調査して」(infinite exploration)は明示された失敗パターン。
- [Claude Code: Manage costs effectively](https://code.claude.com/docs/en/costs) — 2026-07-30参照、official。「improve this codebase のような曖昧な依頼は広域スキャンを誘発する。auth.ts の login 関数に入力検証を追加、なら最小のファイル読みで済む」。巨大出力の前処理: 1万行のログを読ませる代わりにhookが ERROR をgrepして該当行だけ返す(数万トークン→数百トークン)。インクリメンタルに1ファイルずつテストしながら進める。
- [Claude Code: Prompt caching behavior](https://code.claude.com/docs/en/prompt-caching) — 2026-07-30参照、official。planモードやスキル起動は会話末尾への追記であり、それ自体ではキャッシュを壊さない — 段取りを挟むこと自体にキャッシュペナルティはない。**ただしモデル切替は例外**: キャッシュはモデル別のため、planモードで別モデルへ切り替わる設定(`opusplan` 等)では出入りのたびに全履歴が再処理される。この設定で大原則6を適用するなら、モデルを固定するか、plan の出入り回数自体を減らす(モデル切替とキャッシュ失効の運用は `context-economy`)。/rewind と /compact の相対コストと使い分けも `context-economy` 側が一次の置き場であり、本スキルは「捨てる経路があるなら続けるより安い」という行動原則だけを扱う。
- [metsuke](https://github.com/taku7777777/metsuke) — 2026-07-30参照、industry-research(単一利用者のClaude Code全ログ実測に基づくコスト計測・行動変容システム)。「1プロンプト=人間の1指示が引き起こした因果総コスト」を帰属単位とし、サブエージェント費はspawn元プロンプトへ帰属する(時間帯ベースの帰属では総コストの約5%が誤帰属となり、高額プロンプトランキングで数百位→1桁の逆転が起きていた)。プロンプト単価は平均でなく分布で読む(健全域の目安: p50≤$1 / p90≤$8。進行中プロンプトの累積$5超で暴走ガード通知)。依頼文の長さと因果コストは無関係 — 実測では37文字の指示が$4.30(69分の離席で1時間TTLが失効し、425,826tokのプレフィックス再書込が99%を占めた。同セッション全105 requestのrequest単価中央値$0.248の17倍 — プロンプト単価の中央値ではない)。迷走の早期中断(レバーL6)の効果はp99テールとinterrupted率の減少として現れる。

## 採用上の注意 / 更新規律

- 「2回訂正で見切る」「検証手段の同梱」「曖昧依頼は広域スキャンとして課金される」という行動原則は安定しているためSKILL.md側に置く。閾値・金額・コマンド挙動は本ファイルで管理する。
- 四半期ごと、またはClaude Codeのメジャー更新時に再確認する。metsukeの数値はリポジトリの更新で変わりうる。
- p50/p90等の健全域の目安を、他チームのSLAや予算値として転用しない(利用形態・モデル構成で桁が変わる)。
- **定額レーンでのトークン建て読み替え**: ドル建ての目安(p50≤$1 / p90≤$8、進行中プロンプトの累積$5超で暴走ガード)は定額購読レーンでは発火しない。同じ分布をトークン建てで読む — 自分の直近4週のセッション記録から request ごとの総トークン(input + output + cache_creation + cache_read)の p50/p90 を取り、それを基準線にする(取得手段は `llm-cost-observability` のデータソース解説)。基準線は他所から借りず自分の履歴から引く点が要点で、この読み替えは追加の計測基盤なしで閉じる。金額との桁対応が要るときに実測1点(425,826tokのプレフィックス再書込 = $4.30、2026-07時点のモデル構成)を参照してもよいが、これはほぼ純粋なcache writeの1点であり、単価は費目(cache write / cache read / output)とモデルで桁が違う — **この1点から一般の換算率を作らない**。単価そのものが要るときは公式pricingページ(https://platform.claude.com/docs/en/about-claude/pricing.md — 本リポジトリでは `quality/sources.json` の `claude-pricing`)を一次確認先とする。**本ファイルは単価表を持たない**(モデル別$/MTokを転記すると、値の改定時にここが更新漏れの温床になる)。
- 37文字$4.30の実測は離席によるキャッシュ再構築の事例であり、cold cache管理の詳細は `context-economy` 側のエビデンスを参照する。本スキルでは「依頼文の長さはコストの説明変数にならない」ことの例証としてのみ引用し、依頼設計の改善で消える額としては引用しない(SKILL.md 大原則1も同じ限定で書いてある)。
