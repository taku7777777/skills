# セッション・キャッシュ経済のエビデンス

SKILL.mdとカタログが依拠する時点依存の数値・製品挙動の集約。安定原則(離席支配・全面失効は2系統・compactの実コスト構造)はSKILL.md側にあり、本書は「現行値」を持つ。

## 使い方

- 数値を成果物へ引用するときは、参照日と適用条件(認証方式・モデル・プラン)を併記する。
- 実測値(metsuke)は単一ユーザー・単一環境の測定。比率の桁と構造の理解に使い、個別環境の結論には自環境での再測定を求める。

## 一次情報: 価格・キャッシュ倍率

- [Anthropic Pricing](https://platform.claude.com/docs/en/about-claude/pricing.md) — 2026-07-30参照、official。
  - キャッシュ書き込みは基本入力単価の×1.25(5分TTL)/×2.00(1時間TTL)、読み取りは×0.10。5分writeは読み取り1回、1時間writeは2回で元が取れる。倍率はBatch割引(×0.5)等と乗算で重畳する。
  - Sonnet 5の導入価格($2/$10 per MTok)は2026-08-31で終了し$3/$15へ。
  - Claude 4.7以降のモデル(Opus 4.7+・Sonnet 5・Fable 5等)は新トークナイザで同一テキストが約30%多くトークン化される(Sonnet 4.6以前は旧トークナイザ)。単価が同じでも実効コストが変わるため、モデル間の金額比較を単価だけで行わない。
- [Prompt caching(API仕様)](https://platform.claude.com/docs/en/build-with-claude/prompt-caching.md) — 2026-07-30参照、official。
  - キャッシュはプレフィックス完全一致。ブレークポイントは最大4個、過去キャッシュの遡り探索は20ブロックまで。
  - 最小キャッシュ可能トークンはモデル別に512〜4,096で非単調(Opus 5/Fable 5=512、Opus 4.8/Sonnet 5/Sonnet 4.6=1,024、Haiku 4.5=4,096)。下回るとエラーなしで黙ってキャッシュされない。

## 一次情報: Claude Codeのキャッシュ挙動

- [Claude Code: Prompt caching behavior](https://code.claude.com/docs/en/prompt-caching) — 2026-07-30参照、official。
  - プレフィックスのレイヤはtools→system(プロジェクトコンテキスト含む)→messages。上位レイヤの変更は下位を全て無効化する。
  - **全面失効(tools層以下すべて)を招く操作は2系統**: (a)ツール定義の変更 — MCPサーバの接続/切断(定義がプレフィックスにロードされている場合。既定のdeferredでは無傷)、プラグイン着脱、ツール裸名のdenyルール追加。(b)キャッシュキーの変更 — /model切替(キャッシュはモデル別)、/effort変更、fast modeオン。
  - **一部の層だけを作り直す操作**(全面失効とは区別する): Claude Code本体のアップグレード=システムプロンプトが変わるためsystem層以下。/compact=会話層のみ再構築で、システムプロンプト層は再利用され、プロジェクトコンテキストはディスクから再読込される(CLAUDE.md等が未変更ならヒットする)。ただし/compactは要約リクエスト自体が圧縮前の会話全体を読むため、会話が大きいほど、またキャッシュが冷えているほど高い。
  - 壊さない操作: ファイル編集、CLAUDE.mdのセッション中編集(壊さないが反映もされない — 次の/clear・/compact・再起動から)、permission mode切替(planモードの出入りでモデルが変わる設定 — `opusplan` 等 — だけは例外で、出入りのたびにモデル切替として全損する)、スキル/コマンド起動、サブエージェント起動、/rewind(キャッシュ済みプレフィックスへの切り戻しでcompactより安い)。
  - TTLは認証方式で異なる: サブスクリプション=自動1時間(usage credits消費中は5分へ降格)、APIキー/Bedrock/Vertex等=5分(`ENABLE_PROMPT_CACHING_1H=1`で1時間へオプトイン可)。**レーンで12倍違う**ため、「1時間離れなければ大丈夫」は5分レーンでは成り立たない — 既定のAPIキー運用では10〜30分の中断の後の復帰リクエストも全面再書込になる。1時間TTLは書込単価が×1.25→×2.00へ上がるので、TTL内に2回以上読まれる使い方が損益分岐。
  - キャッシュのスコープは実質マシン+作業ディレクトリ単位(worktreeは別ディレクトリ扱い)。長いセッションへの復帰の最初の1ターンが最も高いリクエストになりうる。
- [Claude Code: Context windows](https://code.claude.com/docs/en/context-window) — 2026-07-30参照、official。compact後はシステムプロンプト・project-rootのCLAUDE.md・auto memoryが再注入されるが、path付きルールとnested CLAUDE.mdは消える(該当ファイルの再読で復活)。invoked skill本文はスキルあたり5,000tok/合計25,000tok上限で再注入。

## 一次情報: コスト管理・ベストプラクティス

- [Claude Code: Manage costs effectively](https://code.claude.com/docs/en/costs) — 2026-07-30参照、official。
  - APIはステートレスで毎リクエスト全履歴を再送する。一日中開いていたセッションでの1行の質問も会話全体分の使用量を引く。
  - CLAUDE.mdは200行未満を目安にessentialsのみ(主目的は指示の埋没防止)。MCPツール定義は既定でdeferred(名前のみ常駐)。gh等のCLIはMCPよりコンテキスト効率が良い。hooksの前処理で巨大出力を数万→数百トークンへ絞れる。
  - /usageはcache miss / long contextが直近使用量の10%以上を占めると警告と削減Tipsを表示する。バックグラウンド消費は通常$0.04/セッション未満。
- [Claude Code: Best practices](https://code.claude.com/docs/en/best-practices) — 2026-07-30参照、official。
  - 「同じ問題で2回以上訂正したら、コンテキストは失敗アプローチで汚染されている。/clearして学びを織り込んだプロンプトで再開する方が、ほぼ常に長いセッションに勝る」。
  - kitchen sinkセッション(無関係タスクの混載)は代表的な失敗パターン。「コンテキストが埋まるほどLLMの性能は劣化する」。

## 一次情報: 実測値(metsuke)

- [metsuke(Claude Code利用コストの実測・行動変容システム)](https://github.com/taku7777777/metsuke) — 2026-07-30参照、industry-research(単一ユーザーの実測。34,000超リクエスト)。
  - 離席間隔別のキャッシュ再書込率: 直前リクエストから5分未満=2.6%、5〜60分=2.7%、60分超=73.0%(334リクエスト実測)。連続作業中は既に効率的で、削る対象は離席にほぼ限られる。**測定環境はTTL=1時間**(サブスクリプション相当)であり、「60分」という境界はこの環境のTTLに一致するもので普遍値ではない。5分TTLのレーンでは同じ構造が「5分超」で現れる — 境界は経過時間そのものではなく自環境のTTL。
  - 37文字の指示に$4.30(うち99%が425,826tokの1時間TTL再書込)。復帰コストは指示の長さと無関係にプレフィックス全体で決まる実例。
  - CLAUDE.md 300tok常駐の実効コストは平均プレフィックスの+0.15%。削減は請求に影響しない。
  - 大型スキルの1回ロードは実効約78万tok(常駐2ktokの桁違い)— 常駐整理より呼び出し頻度を先に見る。
  - compactionの実体は喪失側: read 224k→20kへ縮小し新規writeが発生。判断構造(却下案・フェーズ前提)が落ちる。
  - deprioritize目安: TTL失効の再構築費が1日$5未満、または全cache writeの10%未満なら離席施策を優先しない。

## 採用上の注意と更新規律

- 価格・倍率・TTL・最小キャッシュトークンは四半期ごとに再確認する。次回の重点: 2026-08-31のSonnet 5導入価格終了。
- 実測比率(73%等)は環境・プラン・作業スタイルに依存する。桁の理解に使い、施策継続の根拠には自環境の計測(`llm-cost-observability` の領分)を使う。
- 数値が変わっても「主犯は離席」「全面失効は2系統」「compactは無料ではない」という行動原則はSKILL.mdに残す。
